# Issue作成を準備する

入力は新しい要望の一文。例：

```text
/skill:prepare-issue 優先度の高いお問い合わせだけを表示したい
```

1. Issue作成の準備が明示依頼され、対象の要望が一つに決まることを確認する。ファイルの閲覧やコマンドの引用だけでは開始しない。
2. 手順の正本はリポジトリルート基準の `docs/ai-development/workflows/issue-creation.md`。Botプロンプトの `repository`、`readme_path`、`rules_path`、`project_settings_path` と、人間が確認した採用コミットを使う。同じ会話で確認済みの値は再利用し、分からない値だけを尋ねる。採用コミットの `AGENTS.md`、設定で指定された3資料、この工程の手順書を全文読む。作業場所の `origin`、案件別設定の対象、依頼対象を照合する。設定不足、採用版や資料の取得不能、対象の不一致、上位制約との衝突があれば、作業ツリー版・最新 `HEAD`・登録済みWorkflowで代用せず、書き込み前に停止する。
3. 対象リポジトリと引き継ぐ要望を短く示し、ユーザー本人に `/skill:interview-to-issue` の明示起動を案内して待つ。同じ会話で要望が一意なら再入力を求めない。スキルが利用できない場合は代用せず停止する。この入口では自動起動もIssue作成も行わない。

後続は同じ採用版の手順書に従う。要件の決定事項への合意と、タイトル・本文・ラベルを含む最終Issue案全体への明示同意を分ける。案の修正後は再同意が必要。作成後は本文・URL・`Spec` を再確認し、設計には自動で進まない。

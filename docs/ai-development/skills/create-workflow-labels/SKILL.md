# GitHubの工程ラベルを作成する

対象は依頼者が明示した `https://github.com/OWNER/REPO` の1リポジトリ。対象が不明なら確認し、現在のworktreeや `origin` から推定しない。通常のIssue開発Workflowとは別の初期設定作業であり、このファイルの読込やスキルの起動だけではGitHubへ書き込まない。対象案件のルールと設定を確認し、このスキルのラベル定義と矛盾する場合や、案件のルールで対象外の場合は停止する。

## 新規作成時の定義

GitHub CLIに渡す色は `#` なしの6桁の16進数とする。

| ラベル | 色 | 説明 |
| --- | --- | --- |
| `Spec` | `C5DEF5` | Issue作成済み・設計待ち |
| `Design` | `D4C5F9` | 設計・設計確認中 |
| `Todo` | `EDEFF2` | 設計承認済み・開発着手可能 |
| `Imp` | `1D76DB` | 実装・テスト・提出前自己レビュー中 |
| `Review` | `FBCA04` | PR提出済み・CI／レビュー待ち |
| `Rework` | `F29513` | PR指摘修正・再検証中 |
| `MergeReady` | `BFDADC` | 人間のマージ待ち |
| `Done` | `0E8A16` | 対象PRのマージ確認済み（本番配備完了ではない） |
| `Error` | `B60205` | commit・push・PR作成の提出工程失敗 |

## 実行手順

以下の `OWNER` と `REPO` は、依頼者が指定したリポジトリの所有者名とリポジトリ名に置き換える。

1. **認証・対象確認**：`gh auth status --hostname github.com` と `gh repo view github.com/OWNER/REPO --json url,nameWithOwner,viewerPermission` で認証、対象URL、ラベルを作成できる権限を確認する。認証情報は表示・記録しない。失敗や権限不明のまま作成に進まない。
2. **読み取りと承認**：`gh api --hostname github.com --paginate --slurp 'repos/OWNER/REPO/labels?per_page=100'` で全ページを取得する。大文字・小文字を区別せず既存名と比較し、一致するものは新規作成しない。対象URLと、作成予定の名前・色・説明、既存ラベルの表との差分を提示する。取得失敗を「ラベルなし」と扱わない。作成予定がなければ変更せず終了する。不足分の作成は、提示した内容への明示承認と必要なツール承認を得た後に限る。
3. **不足分だけ作成**：書き込み直前に一覧を再取得する。承認時から対象9種の状態が変わっていたら、計画を提示し直して承認を待つ。承認された不足分だけを1件ずつ作成する。次は `Spec` の例。他のラベルも表の値をそのまま用いる。

   ```sh
   gh label create Spec --repo github.com/OWNER/REPO --color C5DEF5 --description 'Issue作成済み・設計待ち'
   ```

   既存ラベルの上書き（`--force`）、改名、削除、色・説明の変更、IssueやPRへのラベル付け・移行は行わない。失敗や結果不明が1件でもあれば残りの作成を止め、一覧を再取得して実状態を確認する。失敗したコマンドをそのまま再送しない。
4. **検証と報告**：一覧を再取得し、今回作成したラベルの名前・色（16進数の大小文字は同一視）・説明を表と照合する。「作成・確認済み」「既存のため維持（定義との差分を含む）」「未作成・未確認」を区別し、対象URLとともに報告する。未確認の反映を成功としない。

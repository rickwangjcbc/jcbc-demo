# 既存PRのレビュー対応とマージ確認を進める

単一のPR番号またはURLと、行う操作を1つ指定する。

```text
/skill:review-pr #43 修正
/skill:review-pr #43 マージ準備
/skill:review-pr #43 マージ後確認
```

1. **対象と操作を確定する。** 閲覧、コマンドの引用、PR番号だけでは工程を開始しない。操作が未指定・曖昧なら確認する。PR番号はBotプロンプトの `repository` 内で解決し、URLの場合もリポジトリを照合する。GitHubの関連付けや確認済みの引き継ぎ記録から対応Issueを一意に特定する。候補が複数ある、根拠がない、または一致を確認できない場合は推測で進めない。
2. **採用版の手順書を使う。** Issue単位の承認記録から採用ルールのコミットを確定し、設計書の版・PRのhead・ローカルの `HEAD` と区別する。その版の `AGENTS.md`、Botプロンプトの `readme_path`・`rules_path`・`project_settings_path` が指す資料と、リポジトリ内の `docs/ai-development/workflows/pr-review-response.md` を全文読む。設定不足、承認記録の不一致・取得不能、資料の取得不能なら停止する。採用版が未記録と確認できた場合は候補を示して人間の承認を待ち、最新版や作業ツリー版で代用しない。登録済みの `demo-pr-review-response` は起動しない。
3. **指定された操作だけを行う。** 各操作で採用版の手順書に従い、対象・権限・個別の操作承認を確認する。ある操作への依頼や承認を、別の操作の許可とみなさない。
   - **修正**：最新の指摘と対象差分を取得する。初回実装と同じIssue専用worktree・ブランチ、`origin`、採用済みの担当継続方式、設計承認・引き継ぎ記録を照合する。対象差分・指摘・修正範囲への明示承認と開始条件が揃ってから `Rework` に変更・再取得し、修正と再検証を進める。各回のAIレビューは別の明示依頼を待ち、差分が変わったら以前の承認や結果を流用しない。提出ゲートを満たし、必要な承認がある場合に限り、手順書の既存PR更新の手順で通常pushし、反映と `Review` を確認する。新規PR用の提出スキルは使わない。完了済みの作業は繰り返さない。
   - **マージ準備**：修正や担当の起動は行わない。手順書第4節に従い、最新headに対する必須CI・人間レビュー・未解決指摘・競合・保護条件と、設計・Issueとの整合を確認する。すべて満たした場合だけ `MergeReady` に変更・再取得し、不足や不明があれば条件を報告する。
   - **マージ後確認**：手順書第5節へ進み、修正用worktree・担当の再開・open PR確認は要求しない。人間によるマージ、マージ先、マージコミットとIssueとの対応を取得し、すべて確認でき、更新の承認がある場合だけ `Done` に変更・再取得する。未マージのクローズは `Done` にしない。

新規PRの作成、マージ、人間の承認の代行、Issueの手動クローズ、worktreeの削除は行わない。

## 担当継続方式の確認記録

文書の更新だけで方式を利用可能とみなさない。同一対話セッション方式は、実地検証・採用承認ともに未記録で、選択しない。

- **同一対話セッション方式の実地確認**：実装・検証役の担当がターンを終えて制御を返し、待機中に自走しないことを観察する。レビューの明示依頼後だけ同じ担当にレビューを依頼し、修正承認前は書き込まず、承認後だけ対象範囲を修正できることを確認する。セッションや差分を照合できない場合は送信・編集せず停止することも確認する。
- **識別と証拠**：環境・ツールとバージョン、検証日時・実施者、担当ID・確認可能なセッション識別情報（タブIDとは別）、worktreeの絶対パスとブランチ、承認・依頼と各ターンの結果が確認できるログの参照先を残す。標準方式でも初回起動と同じ担当の前景再開の実績を区別して記録する。
- **同一対話セッション方式の採用条件**：人間が証拠を確認し、採用方式・利用環境・適用Issue／範囲・承認者・日時・証拠参照先を記録してから使う。進行中のIssueには自動適用せず、適用する場合は採用する改訂コミットを別途確認する。根拠が未確認、または利用条件が変わって同じ証拠を適用できないときは使用しない。

### 工程別引き継ぎ方式の選択

この案件では **JAC Harness の `jcbc-demo-agent` で新規に開発着手する場合**、方式が未指定なら工程別引き継ぎを既定とする。人間が方式を明示した場合はその方式の利用条件を確認する。この既定は採用版に本設定があり、利用環境とBotを照合できる場合だけ使う。対象Issueと採用コミットは承認記録から確認し、選択した方式と根拠を残す。通常の着手前確認として、承認済み設計・専用worktree・操作権限と、実際に使うJAC Harness・Bot・スキル・ツールとの両立を確認する。模擬Issue、検証専用worktree、過去の実地検証ログ、別個の方式採用手続きは不要。この既定は他の環境、旧版を採用中のIssue、既に開発を開始したIssueに自動適用しない。既定の適用可否が不明な場合や継続方式に不一致がある場合は停止する。

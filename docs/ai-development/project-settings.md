## 位置付け

このファイルを案件別条件の正本とします。個人環境のパスを固定せず、パスはリポジトリルート基準で記載します。実設定を今回取得・変更したものではありません。未確認の必須条件は該当工程の開始前に人間が確定してください。
共通ルールは`docs/ai-development/rules.md`、工程ごとの実行条件は`docs/ai-development/lifecycle-guide.md`第12節を参照します。文書の更新・承認と実環境の確認は別の証拠です。

## 担当継続方式の確認記録

文書の更新だけで方式を利用可能とみなさない。同一対話セッション方式と工程別引き継ぎ方式は、実地検証・採用承認ともに未記録で、選択しない。

- **同一対話セッション方式の実地確認**：実装・検証役の担当がターンを終えて制御を返し、待機中に自走しないことを観察する。レビューの明示依頼後だけ同じ担当にレビューを依頼し、修正承認前は書き込まず、承認後だけ対象範囲を修正できることを確認する。セッションや差分を照合できない場合は送信・編集せず停止することも確認する。
- **工程別引き継ぎ方式の実地確認**：実運用と同じJAC Harness・Bot・スキル・権限設定で、実装担当の終了後、明示依頼があるときだけ新規前景セッションへ記録を引き継ぐ。レビューでファイル・ステージ・外部状態が変わらないこと、指摘と差分版への承認後だけ別の修正セッションで再検証すること、再レビューは別依頼まで待つことを確認する。終了不明・差分変更・承認不足で停止することも確認する。
- **識別と証拠**：環境・ツールとバージョン、検証日時・実施者、担当ID・確認可能なセッション識別情報（タブIDとは別）、worktreeの絶対パスとブランチ、承認・依頼と各ターンの結果が確認できるログの参照先を残す。標準方式でも初回起動と同じ担当の前景再開の実績を区別して記録する。
- **採用条件**：例外方式は人間が証拠を確認し、採用方式・利用環境・適用Issue／範囲・承認者・日時・証拠参照先を記録してから使う。進行中のIssueには自動適用せず、適用する場合は採用する改訂コミットを別途確認する。根拠が未確認、または利用条件が変わって同じ証拠を適用できないときは使用しない。

## ローカル検証

現在のルート`README.md`と`package.json`を実行時の根拠とし、変更されていればこの表と整合を確認します。

| 内容 | 現在のコマンド |
| --- | --- |
| 依存復元 | `npm ci` |
| E2Eブラウザ準備 | `npm exec -- playwright install chromium` |
| 単体テスト | `npm test` |

| 型チェック | `npm run typecheck` |
| ビルド | `npm run build` |

| 一括検証 | `npm run check` |

ローカル検証は実装・修正と同じIssue専用worktreeで実行します。最終検証は提出対象と同じ差分で行い、別worktreeの結果では代用しません。実行権限・ネットワーク・ブラウザ依存を確認してから実行します。文書のみの作業は非該当の検証と文書照合などの代替証拠を記録します。上記はローカルコマンドであり、CI設定済みや実行成功の証明ではありません。

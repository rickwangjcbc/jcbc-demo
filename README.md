# JCBC お問い合わせ管理デモ

Issue #1 に基づく、AI駆動開発のデモ用ミニアプリです。
TypeScript + Vite で実装し、UIフレームワークや外部APIは使用していません。

> 合成データ専用です。実在のお客様の情報や個人情報を入力しないでください。

## 必要環境と起動

Node.js 22.12以上（Node.js 26.5.1 / npm 11.17.0で検証）。

```sh
npm ci
npm run dev
```

ターミナルに表示されるローカルURLをブラウザで開いてください。
開発・プレビューサーバーは既定でループバックアドレスだけで待ち受けます。
本番公開の設定は含まれていません。

## 機能とデモ手順

1. 初回アクセスで合成サンプル3件が表示されることを確認します。
2. 件名・内容を入力して「登録する」を押します。初期状態は「未対応」です。
3. 登録したカードの対応状況を「対応中」「完了」に変更します。
4. 「対応状況で絞り込み」を切り替え、「すべて」で解除します。
5. ブラウザを再読み込みして、登録内容・対応状況が保持されることを確認します。
6. 空白のみの入力や上限超過で登録を試し、エラーメッセージを確認します。
7. 「キーワード検索（件名・内容）」へ入力し、入力ごとに一覧が更新されることを確認します。
   件名または内容の部分一致で検索し、英字の大文字・小文字は区別しません。
8. 検索と対応状況を併用し、両方を満たす項目だけが表示されることを確認します。
   検索欄を空にすると検索だけ解除され、対応状況フィルターは維持されます。
   該当しない場合は「該当するお問い合わせはありません。」を表示します。

9. 一覧の「優先度」を「高・中・低」に変更し、再読み込み後も保持されることを確認します。
   新規登録と初回サンプルは「中」です。
10. 「優先度で絞り込み」を切り替え、「すべて」で優先度だけを解除します。
    対応状況・キーワード検索・優先度はすべてAND条件で適用されます。

優先度のない既存データは「中」として読み込み、件名・内容・対応状況を維持します。
読み込み・絞り込みだけでは保存データを書き換えず、次の登録・変更の保存時に優先度を保存します。
不正な優先度を持つ保存データは、既存の破損データと同様に上書きせず操作を停止します。
優先度による並べ替え・自動判定・通知は対象外です。

検索は入力文字列そのものを扱います（前後の空白も検索対象、正規表現ではありません）。
検索・絞り込みは保存済みデータを変更せず、再読み込みで条件はリセットされます。

- 件名は必須・100文字以内、内容は必須・1,000文字以内です。
- 文字数はUnicodeコードポイント数で判定します。絵文字1コードポイントは1文字です。
  結合文字や複数コードポイントの絵文字は見た目の1文字と一致しない場合があります。
- 空白のみは拒否し、保存時には前後の空白を取り除きます。
- 初回だけサンプルを投入します。保存済みデータが空配列でも再投入しません。

## 自動テストと品質チェック

```sh
npm ci
npm exec -- playwright install chromium
npm run check
```

Linuxでブラウザのシステムライブラリが不足する場合は、管理者の承認のうえ
Playwright公式手順に従って必要な依存を導入してください。
ブラウザの保存先が書き込み不可の環境では、書き込み可能な場所を
環境変数 `PLAYWRIGHT_BROWSERS_PATH` で指定し、インストール時と実行時で揃えてください。

```sh
npm test                 # Vitestによる単体テスト
npm run lint             # Google gtsによる規約・書式チェック
npm run typecheck        # TypeScriptのstrict型チェック
npm run build            # 配布用静的ファイルを生成
npm run test:e2e         # ビルド後、Chromiumで画面操作を検証
npm run format           # Google gtsによるTypeScript自動整形
```

`npm run check` はlint・型チェック・単体テスト・ビルド・E2Eを順番に実行します。
E2Eはビルド済みアプリをプレビューサーバーで配信して検証します。
テストデータは合成データのみです。

## 受け入れ条件と検証の対応

- 初回サンプル3件：単体テスト / E2E
- 新規登録・初期状態：E2E
- 必須・文字数上限・空白・境界値：単体テスト / E2E
- 対応状況変更・再読み込み後の保持：E2E
- 状態の絞り込み・解除・該当なし表示：E2E
- キーワード検索の件名・内容部分一致、英字大小、状態併用、空文字解除：単体テスト / E2E
- 検索中の登録・状態変更・保存と再読み込み、検索だけでは保存を変更しない：E2E
- 優先度の初期値・各値の復元・既存データ互換・不正値拒否：単体テスト / E2E
- 優先度変更・再読み込み・三条件AND・優先度だけの解除・該当なし：単体テスト / E2E
- 三条件併用中の優先度保存失敗時のロールバックと保存データ保護：E2E
- 起動方法・テスト実行方法・デモ手順：このREADME
- 追加の安全確認：HTML入力のテキスト表示、保存データ破損、保存不可・容量不足

## コーディング規約

[Google公式TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html)
に準じます。[Google gts](https://github.com/google/gts) の公式設定を使い、
2スペース・シングルクォート等の書式を機械検証します。
strict型チェック、名前付きexport、公開APIのJSDoc、入力検証も採用しています。
スタイルガイドの意味的な規則すべてをlintだけで保証するものではありません。

## データ保護と制約

- データは同一オリジン・同一ブラウザのlocalStorageだけに保存され、外部送信しません。
- 暗号化、ログイン、複数人共有、メール送信、外部AI APIはありません。
- ブラウザの保存データ削除で登録内容が失われます。バックアップ機能はありません。
- 初期状態に戻すには、ブラウザの開発者ツールでこのアプリの
  `jcbc-demo.inquiries.v1` キーだけを削除して再読み込みします。
  登録データが失われるため、デモデータに対してのみ実施してください。
- データ破損時は上書きせず登録操作を停止し、エラーを表示します。
- 保存失敗時は成功表示せず、入力と直前の保存済み状態を維持します。
- 複数タブ同時編集の競合解決は対象外です。デモは1タブで操作してください。
- ブラウザのスクリプトからアクセス可能な保存領域なので、機密情報には使用できません。
- 自動画面テストの対象はChromiumです。Firefox / Safari / 実機は未検証です。

## 依存パッケージ

再現性のためバージョンとlockfileを固定しています。lockfileはnpmで生成します。
`gts` の対話初期化ツールに由来する推移依存 `tmp` は、公開アドバイザリ
[GHSA-ph9p-34f9-6g65](https://github.com/advisories/GHSA-ph9p-34f9-6g65)
の修正版（0.2.6以上）を `overrides` で指定しています。
このアプリはgtsの対話初期化機能を使用せず、lint / formatを検証します。

Google gts 7の推移依存ESLint 9について、npmはサポート終了の警告を表示します。
Google公式設定との互換性を優先して採用しています。
`npm audit` はその時点の既知の脆弱性の検査であり、安全性の完全な保証ではありません。

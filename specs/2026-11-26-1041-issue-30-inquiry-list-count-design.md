# Issue #30 お問い合わせ一覧の表示件数と総件数

## 要件確認書

### 目的・解決したい問題
- [Issue #30](https://github.com/rickwangjcbc/jcbc-demo/issues/30)：検索・絞り込み後に表示される件数を、絞り込み前の総件数とあわせて一覧直上で確認できるようにする。

### 成功基準・完了の判断
- 件数欄は `表示：3件 / 全12件` の形式とし、初期表示と全条件解除後も同じ形式で表示する。
- キーワード・対応状況・優先度を併用して変更または解除したとき、一覧と件数を同時に更新する。
- 新規登録・対応状況変更・優先度変更は、保存成功後に一覧と件数へ反映し、失敗時は直前の件数を維持する。
- 各表示状態と更新結果に加え、対応状況サマリーが検索・絞り込みの影響を受けないことを E2E で確認する。

### 制約
- リスク区分は「通常」。利用者に見える仕様が変わる一方、検索判定や保存形式は変更しない。区分と設計承認者（この会話の依頼者）は会話で確認済み。保存版への設計承認は別途確認する。
- 採用手順・設計時のコード基準は `c66748aee0cb4a1d18ee1c2dddbb3729766b306e`。設計・実装の作業場所は Issue 専用 worktree の `feature/issue-30`。
- テストは合成データ専用とする。

### 内容の個別仕様
- 表示件数は現在の条件で描画される問い合わせカード数、総件数は条件適用前の全問い合わせ数とする。対応状況サマリーは引き続き全問い合わせを集計する。

### エッジケース・暗黙の前提
- 一致がなければ `表示：0件 / 全12件` のように表示し、既存の「該当するお問い合わせはありません。」を残す。正常に読み込まれた空データは `表示：0件 / 全0件` とする。
- 保存データを読み込めない場合は件数欄を非表示とし、既存の読み込みエラーを維持する。件数が不明な状態を 0 件と表示しない。

### 対象外
- 検索・絞り込み条件、判定方法、並び順の仕様の変更。
- 対応状況サマリーの表示・集計方法、保存形式・保存処理、エラー文言の変更。

## 設計書

### 描画と更新
- `index.html` の既存 `#count` は位置を変えず、初期状態を `hidden` にする。`src/main.ts` の `render()` は `available` が偽なら件数欄を非表示のままにし、利用可能なときに件数テキストを設定して表示する。初期データの保存や登録日時の補完保存に失敗し `available` が偽のままの場合も、既存エラーを出し、件数を表示しない。
- `render()` の既存 `filterInquiries()` の結果を使い、その長さを表示件数、`inquiries.length` を総件数とする。同じ結果を既存 `sortInquiries()` に渡して一覧を描画する。並べ替えは要素数を変えない。別の絞り込みや件数用の状態は作らない。
- 検索入力・各絞り込み・既存の高優先度ショートカット・並び順のイベントから既存の `render()` を使い、件数と一覧を同じ描画処理で更新する。0 件案内と `summarizeInquiries(inquiries)` の処理は維持する。
- 新規登録・対応状況変更・優先度変更は、既存の `save()` が保存後に `inquiries` を更新し、成功時にだけ再描画する経路を保つ。失敗時は既存エラーを表示し、保存済みデータ・一覧・件数は維持する。対応状況・優先度の選択肢を元の値に戻す既存処理も維持する。

### 変更対象と検証方針
- 実装対象は `index.html` と `src/main.ts`。件数の E2E は `tests/e2e/inquiry-count.spec.ts` に追加し、`tests/e2e/summary.spec.ts` の旧件数の期待値だけを `表示：3件 / 全3件` に更新する。既存のサマリー検証は維持する。

| 完了条件 | E2E で確認すること |
| --- | --- |
| 初期表示・全条件解除 | 合成データ 4 件で `表示：4件 / 全4件` とカード 4 件を確認。検索と両絞り込みを適用後、すべて解除して同じ状態に戻ることを確認。 |
| 条件の併用・変更・解除 | キーワード・対応状況・優先度を順に変更・解除する。各操作後に `#count` の文言と実際のカード数を確認し、各状態でサマリーの 4 項目が初期値のままであることを確認。 |
| 該当なし・正常な空データ | 不一致の検索で `表示：0件 / 全4件`、保存済み空配列で `表示：0件 / 全0件`。どちらも件数欄が見え、カードがなく既存の案内が表示されることを確認。 |
| 読み込み失敗 | 破損 JSON と `localStorage.getItem` の例外で `#count` が非表示となり、既存の読み込みエラーが表示されることを確認。初期化・日時補完保存の失敗時も、補完保存エラーと非表示を確認。 |
| 保存成功 | 検索中に条件に一致する問い合わせと一致しない問い合わせを登録し、前者は表示件数・総件数、後者は総件数だけが増えることを確認。対応状況・優先度はそれぞれ適用中の条件から外れるように変更し、保存後にカードと表示件数だけが減ることを確認。 |
| 保存失敗 | 正常に読み込んだ後に `localStorage.setItem` を失敗させ、登録・対応状況変更・優先度変更のそれぞれでエラーが見え、直前のカードと両件数が維持されることを確認。変更操作では選択値も元に戻ることを確認。 |

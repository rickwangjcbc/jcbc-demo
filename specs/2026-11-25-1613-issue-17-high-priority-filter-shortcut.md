# Issue #17：高優先度のお問い合わせをワンクリックで絞り込む

## 要件確認書

### 目的・解決したい問題

- 対応担当者が、優先度の選択欄を開かずに、高優先度のお問い合わせを一覧で確認できるようにする。

### 成功基準・完了の判断

- 初期表示は従来どおり。ボタンを1回押すと優先度の選択値が「高」になり、一覧に即時反映される。キーワード検索・対応状況・並び順は維持する。
- 再押下でも「高」のままとする。既存の優先度選択欄で「すべて」を選ぶと、優先度の絞り込みだけが解除される。

### 内容の個別仕様

- 「優先度で絞り込み」の選択欄の直後（「並び順」の前）に「優先度の高いお問い合わせを表示」ボタンを置く。キーボードで操作でき、トグルにはしない。

### エッジケース・暗黙の前提

- 一致が0件なら、既存の「該当するお問い合わせはありません。」を表示する。
- 保存データの読み込みに失敗して既存の一覧操作が無効になる場合、このボタンも無効にする。既存のエラー表示は変更しない。

### 対象外

- 初期表示の変更、再押下による解除、ショートカット専用の0件案内、フィルター状態の永続化、データ形式や保存処理の変更。
- 今回は設計のみ。実装・提出は別工程とする。

### 画面と処理

- `index.html`：優先度選択欄の直後に標準の `button`（`type="button"`）を追加する。表示文言をアクセシブルな名前とし、標準のキーボード操作を使う。
- `src/main.ts`：ボタン押下時に既存の `priorityFilter.value` を `高` に設定し、既存の `render()` を呼ぶ。ボタン専用の状態は持たず、既存の選択欄・検索・対応状況・並び順の入力値をそのまま使う。選択欄で優先度を変更・解除する処理は変えない。
- ボタンの無効化条件は既存の優先度選択欄と同じ `!available` とする。読み込み失敗時のエラー表示や保存処理には触れない。全件数・対応状況サマリーの集計と、未保存メモの保持も変更しない。

### 受け入れ条件とテスト方針

実装後、既存の `tests/e2e/app.spec.ts` に沿って Playwright E2E を追加する。複合条件の確認には、登録日時の異なる一致データを2件以上と、検索語・対応状況・優先度の各条件で除外される合成データを用意し、表示対象と順序を確認する。

| 受け入れ条件 | E2E で確認すること |
| --- | --- |
| 初期表示の維持 | 初回表示で優先度は「すべて」、並び順は「登録が新しい順」で、従来のサンプル3件が表示される。 |
| 1回で即時反映・他条件を維持 | 検索語・対応状況・「登録が古い順」を設定してボタンを押す。追加操作なしで優先度が「高」になり、一致する問い合わせだけが古い順に表示される。他の入力値は変わらない。 |
| 再押下で解除しない | もう一度押しても選択値・表示対象・順序が変わらない。 |
| 既存の選択欄で解除 | 「すべて」を選ぶと、検索語と対応状況に一致する他の優先度も表示され、検索語・対応状況・並び順は維持される。 |
| 0件時は既存案内 | 「高」で一致しない条件で押すと、既存の0件案内が表示される。 |
| キーボード操作 | ボタンにキーボードでフォーカスして操作すると、クリック時と同様に「高」が適用される。 |
| 読み込み失敗時 | 既存の読み込みエラーを表示し、優先度選択欄とボタンが無効になる。既存データは上書きされない。 |

# Issue #36：お問い合わせの件名・内容を一覧で編集する

## 要件確認書

対象：[rickwangjcbc/jcbc-demo #36](https://github.com/rickwangjcbc/jcbc-demo/issues/36)。通常案件（既存機能への編集操作の追加。合成データ専用で、認証・権限・保存形式の変更やデータ移行なし）。依頼者がこの会話で区分と同じタブ内に限る仕様を確認済み。設計書の承認は未取得。採用手順版：`0eeaa7150663dbbad2375f091e003a3e286252a1`。

### エッジケース・暗黙の前提

- カード内の「編集」で保存済みの件名・内容を編集し、「保存」の成功時だけ反映する。「キャンセル」は確認なしでそのカードの下書きだけを破棄する。
- 件名と内容は必須。空白のみは不可。前後の空白を含めた入力全体を Unicode コードポイントで数え、件名100、内容1,000まで。検証後に前後の空白を除いて保存する。
- 入力エラーや保存失敗時はエラーを表示し、編集欄と入力を維持する。保存済みの値を変えず、成功表示もしない。
- 複数カードの下書きを独立して保持する。検索・絞り込みで非表示になっても同じページ内で復元する。未保存値は検索に使わず、再読み込み・ページを閉じて開き直したときには復元しない。
- 保存成功後は検索・絞り込み・並び順を変えずに一覧を再描画する。変更後の件名・内容で一致しなくなったカードを外し、表示件数も同時に更新する。
- 更新するのは対象IDの件名・内容だけとする。対応状況・優先度・対応メモ・登録日時は維持し、**同じタブ内**で編集中に別操作が保存した値も上書きしない。

### 対象外

- 専用編集画面、自動保存、ページを閉じた後の下書き復元、キャンセル確認。
- 件名・内容の編集操作による対応状況・優先度・対応メモ・登録日時の変更。
- 別タブとの同時編集・変更の同期や競合解消。保証範囲の明記は設計承認時に Issue 本文にも反映する。

## 設計書

### 画面と状態

`src/main.ts` の一覧描画に、通常表示の「編集」と、編集時のラベル付き件名入力・内容入力、「保存」「キャンセル」を追加する。既存の対応状況・優先度・対応メモの操作は維持し、「保存」と「メモを保存」は区別する。編集開始時は最新の保存済み値を初期値にする。通常表示は `textContent`、入力の復元は `.value` を使う。

既存の `memoDrafts` と別に、問い合わせIDをキーとするページ内の Map に編集中の件名・内容の生の値を保持する。入力のたびに Map を更新し、一覧の再描画では Map の有無で編集状態を復元する。表示中の DOM に依存せず、非表示でも保持する。Map は永続化しない。キャンセルは対象IDの下書きだけを削除し、保存せず再描画する。

### 保存・失敗時の処理

1. 対象IDの下書きに既存の `validateInquiry`（`src/inquiries.ts`）をそのまま適用する。コードポイント数と異なる制限で入力を切り詰めない。検証に失敗した場合は既存のエラー領域に理由を出し、下書き・保存済みデータに触れず終了する。
2. 検証に通った値を `trim()` し、保存ボタンを押した時点の `inquiries` から対象IDを探し、件名・内容だけを差し替えた次の配列を作る。編集開始時のカード全体を保存に使わない。登録日時の補完フラグ、他カード、未保存メモも維持する。
3. 既存の `save(next)` で `jcbc-demo.inquiries.v1` に保存する。書き込みが失敗した場合は既存のエラー表示を使い、`inquiries` と下書きを更新せず、その場で再試行またはキャンセルできるようにする。入力エラー・保存失敗のどちらでも既存の成功通知を消す。
4. 保存成功時のみ、対象IDの下書きを削除し、エラーを解除して一覧外の既存通知領域に成功を表示する。既存の `render()` を呼び、保存済みの `inquiries` から同じ検索・絞り込み条件で一覧と件数を更新する。対象カードが一覧から外れても成功通知は確認できる。並び順・全件集計の算出方法は変えない。

### 変更範囲と検証

主な実装対象は `src/main.ts` と新規の `tests/e2e/inquiry-edit.spec.ts`。入力検証、データ型、保存スキーマ、検索関数は既存のものを再利用する。依存追加・データ移行は行わない。

| 確認対象 | E2E で確認する結果 |
| --- | --- |
| 保存・再読み込み | 編集前の値を初期表示。前後の空白を含む有効な入力を明示保存し、通常表示と再読み込み後の両方で整形済みの値を表示する。 |
| キャンセル | 確認ダイアログなしで通常表示に戻り、元の値が残る。 |
| 入力チェック | 空欄・空白のみを拒否。件名100／101、内容1,000／1,001の境界を、複数コードユニットの文字と前後の空白を含む入力で検証する。不合格時は入力・編集欄・保存値が変わらず、成功通知が出ない。 |
| 保存失敗 | 対象保存の `Storage.setItem` をテスト内で一度だけ失敗させる。エラー、編集欄・入力の維持、保存内容の不変、成功通知なしを確認し、同じ入力で再試行できることを確認する。 |
| 複数カード | 2件を同時に編集し、一方を保存・キャンセルしても、他方の編集状態・入力・保存済みの値が変わらない。 |
| 検索・絞り込みと復元 | 検索・対応状況・優先度の絞り込みでそれぞれ非表示にし、解除すると下書きが復元する。下書きだけに含まれる語では一致しない。 |
| 下書きの破棄 | 再読み込みと、同じブラウザコンテキストでのページの閉じ直しを別々に確認。未保存値が復元せず、保存済みの値を表示する。 |
| 保存後の検索と件数 | 一致中のカードを不一致になる値に保存し、検索条件が保持され、カードが消え、表示件数だけが減る。検索条件を変更すると保存後の値で一致する。 |
| 他項目の維持 | 編集中に同じカードの対応状況・優先度・対応メモを別操作で保存し、その後に件名・内容を保存する。再読み込み後も各項目の最新値と元の登録日時が残る。 |

実装後は `npm run test:e2e` と既存の回帰検証を含む `npm run check` で確認する。設計段階では実行しない。

### 制約
- TypeScript + Vite、既存のDOM描画、localStorage保存を維持する。
- 新しい依存関係、外部API、汎用的なデータ移行基盤は追加しない。
- 保存キー `jcbc-demo.inquiries.v1` と保存配列順を維持する。
- 既存の登録・対応状況・優先度・検索・絞り込み・対応メモを保護する。
- 文書は実装・レビュー担当者向けの日本語Markdownとする。

### 内容の個別仕様
- 一覧上部の「並び順」に「登録が新しい順」「登録が古い順」を用意し、変更を即時反映する。
- 初期値は「登録が新しい順」。選択はページ内で維持し、再読み込みで初期値へ戻す。
- 検索・対応状況・優先度のAND条件に一致するデータを、登録日時で並べ替える。
- 同一日時では、両方向とも元の保存配列順を維持する。
- 並べ替えだけでは保存データを変更せず、検索・絞り込み条件やID別の未保存メモも維持する。
- 新規登録時に登録日時を保存し、対応状況・優先度・メモの編集では変更しない。
- 既存データの登録日時の欠落・不正値は、対象全件共通の読み込み時刻で補完し、補完であることも保存する。
- 有効な保存済み日時と補完の区別は、再読み込み後も維持する。
- JST・秒までの24時間表記で「登録日時：YYYY/MM/DD HH:mm:ss」または「登録日時（補完）：YYYY/MM/DD HH:mm:ss」を表示する。

### エッジケース・暗黙の前提
- 日時項目が存在しても、`null`、不正文字列、型違いなどは補完対象とする。
- 初回の合成サンプル3件には共通の初回読み込み時刻を設定し、補完値として保存・表示する。
- 日時補完時も、既存の登録内容・対応状況・優先度・対応メモなどを維持する。
- 補完保存失敗時はエラーを表示し、登録・編集を停止する。直前の保存済みデータを維持し、補完完了としない。
- 日時以外の既存データ検証は維持し、破損JSONや不正な必須項目を日時補完によって救済しない。

### 対象外
- 更新日時・優先度など、登録日時以外での並べ替え。
- 並び順選択の永続保存、利用者による日時編集、過去の実際の登録日時の復元。
- 今回の機能実装、テスト実行、GitHubの更新、commit、push、PR作成。
- 複数タブ競合の解決、外部同期、バックアップ機能。

## 詳細設計書

### 1. 根拠と現行構成

- 要件の一次情報：[Issue #9](https://github.com/rickwangjcbc/jcbc-demo/issues/9)。確認時点では `OPEN`、ラベル `Todo`、コメント0件。
- 追加決定：不正日時も補完する。初回サンプルも共通時刻による補完として扱う。
- `src/inquiries.ts`：問い合わせ型、保存データの読込・検証、検索と絞り込み、入力検証。
- `src/main.ts`：localStorage入出力、操作可否、DOM描画、登録・編集イベント。保存成功時だけ `inquiries` を更新する。
- `index.html`：登録フォームと一覧操作欄。並び順選択欄は登録フォームの外に置ける構成。
- 未保存メモは既に `memoDrafts: Map<string, string>` でID別に保持し、再描画時に復元している。
- テストはVitestとPlaywright（Chromium）。実行コマンドはREADMEと `package.json` に定義済み。

### 2. データ構造

既存の `Inquiry` に次の必須項目を追加する。保存済み旧データは読込時に正規化し、アプリ内では必ずこの型を満たす。

| 項目 | 型 | 意味 |
| --- | --- | --- |
| `createdAt` | `string` | UTCのISO 8601文字列。生成は `Date.prototype.toISOString()` を使用 |
| `createdAtEstimated` | `boolean` | `true` は読み込み時刻による補完、`false` は通常の新規登録 |

- 保存形式は従来どおり問い合わせオブジェクトの配列とし、別キー・ラッパー・形式バージョンは追加しない。
- この機能が生成する日時は `YYYY-MM-DDTHH:mm:ss.sssZ`。有効性は文字列であること、有限の日時へ変換できること、変換後の `toISOString()` と元文字列が一致することで判定する。正規形式以外は不正日時として補完する。ブラウザ依存の曖昧な日時解釈を避ける。
- 日時が不正なら元の補完フラグにかかわらず、日時を共通補完時刻、フラグを `true` に置き換える。
- 有効日時でフラグがない場合は `false` として正規化し、起動時に保存する。既存の `true` / `false` は維持する。有効日時でフラグが存在するがbooleanでない場合は、日時以外のデータ不正として読み込みを停止する。
- 保存済みデータの日時以外の項目をスプレッドで引き継ぐ。既存の優先度・メモ欠落時の補完は維持する。

### 3. ロジックの配置

`src/inquiries.ts` 内で必要な純粋関数だけを追加・調整する。以下の関数名は実装時の推奨名とする。

| 関数 | 責務 |
| --- | --- |
| `loadInquiries(raw, loadedAt)` | 既存検証と日時正規化を行い、正規化後配列を返す。`loadedAt` は呼出元で1回取得したUTC文字列 |
| `sortInquiries(inquiries, order)` | 元配列を変更せず、日時と元配列内の位置に基づく表示用配列を返す |
| `formatCreatedAt(createdAt)` | 有効日時をJSTの指定書式に変換する |

- `loadInquiries` はlocalStorageを操作しない。時刻を引数として受けることで、全件共通時刻とテストの再現性を確保する。
- 保存要否は呼出元で元のJSON配列と正規化後の配列を対応付け、日時の補完または補完フラグの追加が1件でもあるか判定する。`raw === null` では初回保存が必要。
- 単なるJSON文字列の比較は使わない。プロパティ順や空白の違いだけで起動時保存しない。
- 日時の正規化規則は `loadInquiries` に集約する。呼出元では返却値と元データの日時2項目だけを比較し、規則自体を重複実装しない。

### 4. 起動と補完保存

1. `available = false` で開始する。
2. localStorageの既存キーを読み込み、起動処理内で `new Date().toISOString()` を1回だけ取得する。
3. `loadInquiries(raw, loadedAt)` でJSON構造と既存項目を検証し、候補配列を生成する。検証失敗時は保存せず既存の読込エラーを表示する。
4. 初回サンプル生成、日時補完、補完フラグ追加が必要なら、候補配列全体を同じキーへ1回だけ保存する。
5. 保存成功時、または保存不要時だけ、候補配列をアプリ内状態として採用し、`available = true` にして描画する。
6. 補完保存失敗時は候補を確定状態として採用せず、`available = false` を維持する。保存済みの元データを削除・再保存・初期化しない。

補完保存失敗時の表示文案：

> 登録日時の補完データを保存できませんでした。登録・編集を停止しています。保存設定や空き容量を確認して再読み込みしてください。既存データは変更していません。

- 現行の起動失敗時と同じく一覧カードは描画せず、登録フォーム・検索・絞り込み・並び順を無効にする。編集UIを生成しないため編集もできない。
- 登録・編集ハンドラーでも利用可能状態を確認し、利用不可時に保存処理へ進ませない。
- 自動再試行や再試行ボタンは追加しない。環境を直して再読み込みしたとき、補完未完了の元データから、その再読み込み時刻で再試行する。
- 補完済みデータと有効な通常日時だけなら、再読み込みによる日時書換えも保存も行わない。
- 保存済み空配列は空配列のままとし、サンプル投入・補完保存を行わない。

### 5. 新規登録と編集

- 新規登録の入力検証が成功した後、保存候補の生成時に登録日時を1回取得し、`createdAtEstimated: false` とともに新規要素へ設定する。
- 保存配列への追加は現行どおり末尾追加とする。表示上の先頭挿入のために配列を並べ替えない。
- 保存失敗時は現行の保存処理に従い、フォーム入力と直前の保存済み状態を保持する。再送信は新しい登録試行なので、その時点の時刻を使用する。
- 対応状況・優先度・メモは既存のID指定 `map` とスプレッド更新を継続し、日時2項目を変更しない。
- 通常の登録・編集保存失敗と、起動時の補完保存失敗を区別する。前者は既存どおり入力を保持して再試行でき、後者は起動を完了しない。

### 6. 並べ替えと画面状態

- `index.html` の一覧操作欄に `<label for="sort-order">並び順</label>` と `select#sort-order` を追加する。
- 選択肢の内部値は `newest` / `oldest`、表示はそれぞれ「登録が新しい順」/「登録が古い順」とする。先頭の `newest` を初期選択とする。
- `render()` は既存の `filterInquiries` の結果に `sortInquiries` を適用する。
- 絞り込みは保存配列の相対順を維持するため、絞り込み後の位置を同一日時のタイブレークに使っても保存配列順と一致する。
- 並べ替えでは各要素に入力配列内の位置を対応付け、第一キーを時刻の昇順／降順、第二キーを位置の昇順として比較する。降順でも第二キーは反転しない。
- 元配列や問い合わせオブジェクトは変更しない。並べ替えのイベントは再描画だけを行い、`save()` を呼ばない。
- 並び順は選択欄の値を参照する。再描画で選択欄を作り直さず、登録時の `form.reset()` の対象にも含めない。
- 検索・絞り込み・登録・各編集後の描画でも現在の並び順を適用する。条件に合わない新規データは既存仕様どおり表示しない。
- `memoDrafts` は並べ替え時に消去しない。カードを再生成しても問い合わせIDで未保存入力を復元する。
- ブラウザによるフォーム値復元に依存しないよう、ページ起動時に並び順を明示的に `newest` に設定する。

### 7. 日時表示

- 各カードの本文の後、編集操作欄より前に表示専用の日時要素を追加する。入力欄は設けない。
- `Intl.DateTimeFormat` に `timeZone: 'Asia/Tokyo'`、`calendar: 'gregory'`、`numberingSystem: 'latn'`、`hourCycle: 'h23'` を指定する。
- 年・月・日・時・分・秒を `formatToParts()` で取得し、年4桁、その他2桁に揃えて `YYYY/MM/DD HH:mm:ss` を組み立てる。ロケール依存の区切りや午前午後表記を直接使わない。
- 表示は秒までだが、保存と比較はミリ秒を維持する。同じ秒に見えてもミリ秒が異なる場合は時刻差に従う。
- `createdAtEstimated` に応じて「登録日時：」または「登録日時（補完）：」を付ける。`textContent` で表示し、HTMLとして解釈しない。

### 9. テスト設計と完了条件の対応

| 対象 | 単体テスト | E2Eテスト |
| --- | --- | --- |
| 初期値・即時切り替え | 異なる日時の昇順・降順 | 初期 `newest`、切り替え後のカード順 |
| 同一日時の順序 | 同一日時を含む配列を両方向に比較。元配列と要素の不変性 | 固定日時のデータを投入し、両方向と絞り込み後の順序 |
| 選択の維持 | 検索・状態・優先度AND結果との合成 | 古い順で検索・両絞り込み・登録・状態変更・優先度変更・メモ保存後も選択維持 |
| 再読み込み | 該当なし | 古い順から再読み込みして新しい順へ戻る |
| 非保存操作 | 並べ替え前後の入力配列を比較 | 補完完了後に保存文字列と書込回数を取得し、並べ替え・検索・絞り込みで不変 |
| 未保存メモ | 該当なし | 複数IDに異なる下書きを入力し、切り替え・一時非表示・復帰後も維持 |
| 新規登録日時 | 通常日時の読込維持 | 固定時計で登録し、日時と `false` を保存。編集・再読み込み後も同値 |
| 欠落・不正日時の補完 | 欠落、`null`、空文字、不正文字列、数値、真偽値、配列、オブジェクト、存在しない日付を補完 | 有効日時と欠落・不正日時の混在データを投入し、対象だけを補完 |
| 共通時刻と項目保護 | 固定の `loadedAt` と全補完値の一致。ID・件名・内容・状態・優先度・メモ・配列順を維持 | 補完保存後の全対象日時が一致し、他項目と保存配列順も維持 |
| 補完の永続化 | 有効日時とbooleanフラグを維持 | 補完保存後に時計を進めて再読み込みし、日時・フラグ・表示が不変で再保存なし |
| 初回と空配列 | サンプル3件の共通日時と `true`。保存済み空配列は空のまま | 初回サンプルの補完表示と保存、空配列での再投入なし |
| 補完保存失敗 | 読込関数自体は保存を行わない | 旧データ投入後に `setItem` を失敗させ、エラー・操作停止・元の保存文字列維持・成功通知なし |
| 失敗後の復旧 | 該当なし | 保存可能にして時計を進め、再読み込みで新しい共通時刻による補完成功 |
| JST表示 | UTC日付境界、JST午前0時、1桁の月日時分秒、うるう日、ミリ秒差 | UTCと `America/Los_Angeles` のコンテキストで同じJST文言。通常・補完の両表示 |
| 既存データ保護 | 壊れたJSON・不正必須項目・重複ID・不正メモは既存どおり拒否 | 既存の読込不能・容量不足テストを維持 |
| 既存機能の回帰 | 既存単体テスト全件 | 既存の登録・状態・優先度・検索・絞り込み・メモの全テスト |

- 補完対象外の有効日時と保存済み補完日時を含む混在ケースを必ず用意する。
- E2Eの時刻はブラウザの時計を固定して再現する。ストレージ投入は初回だけとし、再読み込みでデータを再投入して永続化不具合を隠さない。
- 保存失敗テストは旧データ投入を済ませてから対象キーの保存を失敗させ、元データの完全一致を確認する。
- 未保存メモは別IDへ移っていないことも確認する。

## 前提条件

- 読者は既存のTypeScriptコードとVitest／Playwrightの基本を理解している実装・レビュー担当者とする。
- 項目名・関数名・選択欄の内部値は本設計の推奨名とし、実装時は意味と保存契約を保ったうえで既存命名に合わせる。
